# 安全な OCR 補助文字復元

## 目的

PaddleOCR を本文の正としたまま、Tesseract が返したカギ括弧、句読点、小書きかな、長音記号、改行だけを、十分に一致した本文の間で復元する。

## 調査結果

`7つの会議` の再実行では、PaddleOCR は漢字本文を比較的正しく返す一方で記号を欠落させ、Tesseract は記号を多く返す一方で通常文字にも誤認識を含んでいた。現在の `PunctuationMerger` は補助 OCR の不一致区間が補助文字だけの場合にしか採用しないため、Tesseract の誤字に隣接した正しい `。`、`「`、`ー` を捨てている。

## 選択肢

1. Tesseract の全文を採用する。句読点は改善するが、`会識` や `営業一誤` のような本文誤認識が増えるため採用しない。
2. 辞書や文脈推測で本文を置換する。`こと` や固有名詞の修正も狙えるが、誤修正を防げないため採用しない。
3. 両 OCR の一致区間をアンカーにして、Tesseract の補助文字だけを採用する。本文は変更せず今回の記号欠落を改善できるため採用する。

## 設計

LCS で得た一致文字の前後に十分な連続一致があり、両者の不一致区間が短い場合に限る。Paddle 側の不一致区間が空なら、Tesseract 側の補助文字を本文文字の誤認識を無視して挿入する。Paddle 側にも本文が残っている場合は、Tesseract 側の先頭に連続する補助文字だけを挿入する。これにより `テナーブル` の余分な `ナ` を無視して `テブル` へ `ー` を補い、`。「ハつ` から `。` と `「` だけを補える。

通常文字、漢字とカタカナの置換、単語補正は行わない。既存の重複カギ括弧正規化は維持する。

## 検証

- `会議テブル` と `会識テナーブル` から `会議テーブル` を得る。
- 本文誤認識を含む補助 OCR から、`。` と `「`、`」` のみを復元する。
- 補助 OCR の本文誤字の後ろにある小書きかなは採用しない。
- 既存の句読点・カギ括弧・小書きかな・長音の全テストを維持する。
