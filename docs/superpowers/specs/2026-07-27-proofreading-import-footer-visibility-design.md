# 校正済みテキスト取込み画面のボタン常時表示 設計

## 背景

`ProofreadingImportWindow` は、検証結果の詳細を上部の `Summary` に表示し、
候補一覧を中央、保存・キャンセルボタンを下部に配置している。
`Summary` が `Auto` 高さの行にあり、詳細件数が多いと必要高がウィンドウ高を
超えるため、中央の `*` 行が縮退した後も下部ボタンが画面外へ押し出される。

## 採用する設計

上部の詳細表示を、最大高さを持つ縦スクロール可能な領域にする。
候補一覧は現在の `*` 行を維持し、保存・キャンセルボタンは現在の最下部
`Auto` 行を維持する。これにより、詳細が短い場合は従来どおり必要な高さだけを
使い、詳細が長い場合だけ詳細欄内部でスクロールする。

ウィンドウ全体をスクロール対象にはしない。主要操作ボタンがスクロール位置に
依存して再び見えなくなるためである。詳細を別画面や折りたたみ表示にもせず、
既存操作を変えない最小修正とする。

## UI動作

- 検証詳細が少ない場合、詳細欄に不要な余白を追加しない。
- 検証詳細が多い場合、詳細欄に縦スクロールバーを表示する。
- 候補一覧は残りの高さを使用する。
- 「キャンセル（保存しない）」と「選択ページを保存」は、ウィンドウの
  `MinHeight` でも常に下部に表示する。
- 候補の選択、警告絞込み、差分表示、保存処理の意味は変更しない。

## テスト

XAML回帰テストで次を確認する。

- `Summary` が縦スクロール可能なコンテナー内にある。
- 詳細コンテナーに最大高さが設定されている。
- 候補一覧が `Grid.Row="2"` の `*` 行に残っている。
- 操作ボタン領域が `Grid.Row="3"` に残っている。
- 保存・キャンセルボタンに名前を付け、固定フッター内に存在する。

実装後はDebug/Releaseビルド、全.NETテスト、Pythonテストを実行する。
リリースZIPは作成せず、必要な場合のみ `package.ps1 -SkipArchive` を使う。
